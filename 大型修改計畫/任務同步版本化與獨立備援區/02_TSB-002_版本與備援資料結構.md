## 目標

讓現行 UUID 保持唯一、每份歷史版本以 `backup_id` 獨立操作。不能直接替 UUID 加尾號，因為目前關聯欄位、觸發網址格式與 API 都依賴原始值。

## 資料契約

| 結構 | 必備欄位／限制 |
| --- | --- |
| 現行 `SendTask` | 新增 `local_generation_id`、`sync_revision`；不列入遠端同步欄位 |
| 備援標頭 `TaskBackup` | `backup_id`、`source_task_uuid`、`source_create_ut`、`source_local_generation_id`、名稱、原組織、備援時間、原因、快照格式版本 |
| 固定 payload | 完整 task snapshot、stats snapshot 與統計基準時間、匯出需要的樣板 metadata snapshot |
| 可更新觀測 | 最近遠端狀態、檢查時間、最近遠端建立時間、已確認重建時間 |
| 備援明細 `TaskBackupDetail` | `backup_id` 與原始明細欄位，保留所有 `second_*` 與完整事件陣列 |
| 唯一鍵 | 現行 `sendtask_uuid` 唯一；備援標頭 `(source_task_uuid, source_local_generation_id)` 唯一；備援明細 `(backup_id, uuid)` 唯一 |
| 外鍵 | 備援明細參考備援標頭，刪除僅 cascade 該份備援；不得參考現行任務而隨現行刪除 |

備援的原始 UUID、原始建立時間可重複；不得對全部歷史明細的 `uuid` 加全域唯一限制。來源建立時間與時間戳以既有秒級資料型態保存，備援／檢查時間用 `TIMESTAMPTZ`。

## 工作項目

1. 新增兩個 model 與必要索引，維持原模型 API。
2. 沿既有 `init_db`／`schema_migrations` 寫可重跑的非破壞性 migration。
3. 為既有現行資料補本地版本與初始修訂，不重算／刪除寄送明細。補值程序不能每次重啟就換版本。
4. 明細欄位只做必要共用，可用局部 mixin 或等價方法，避免兩份欄位定義長期不一致；不大規模重構 models。
5. 定義 payload 格式版本與序列化方式，完整事件不只保存最後一次；組織需能直接用於安全篩選。
6. 在歷史統計沒有可信計算時間的既有資料上標示未知，不把備援時間冒充計算時間。

## 驗收條件

- [x] 全新資料庫與有舊資料的資料庫都能套用 migration，連續套兩次不改變資料或版本識別。
- [x] 舊任務、統計、明細與觸發陣列原值保持完整。
- [x] 同 source UUID 的多個備援、同原始明細 UUID 在不同備援都可存在。
- [x] 同一個本地版本不能重複產生兩份備援。
- [x] 刪除備援 X 不影響備援 Y、現行任務或其他客戶關聯。
- [x] 備援 model／查詢不依賴現行 SendTask row 仍存在。

## 聚焦驗證

用隔離 PostgreSQL 測試資料庫驗證 constraint、migration 與 cascade；不可指向現行 Compose 資料庫。僅編譯 SQL 或 mock 不能取代實際 constraint 驗證。

### 實際交付契約

- Migration：`20261105_task_backup_versions_v1`，實作於 `repository/task_backup_schema.py`，由 `init_db` 的既有 create_all 後呼叫；交易由呼叫端擁有，使用 transaction advisory lock 保護同 migration 並發。既有 marker 存在時不重做。
- SendTask 新增 `local_generation_id VARCHAR(36) NOT NULL DEFAULT gen_random_uuid()::text`、`sync_revision BIGINT NOT NULL DEFAULT 0`。只補 NULL，不更新已有 generation／revision，之後新建任務可使用資料庫預設值；不更動 SENDTASKS_COLUMNS。
- `TaskBackup`／`task_backups`：backup_id 為 String(36) 主鍵、資料庫預設 UUID；來源 UUID、nullable source_create_ut、來源本地 generation、名稱、owner_gids TEXT[]、TIMESTAMPTZ 備援時間、reason、snapshot_schema_version（預設1）、task_snapshot JSONB、nullable stats_snapshot JSONB／stats_snapshot_at、mail_template_snapshot JSONB（預設空 object），以及 unchecked/present/missing/error 遠端觀測與時間／來源建立時間。
- `TaskBackupDetail`／`task_backup_details`：獨立 BIGINT id 主鍵、backup_id 外鍵 ON DELETE CASCADE、原 uuid／sendtask_uuid；透過 SendLogFields 共用所有郵件資料與 second_* 事件欄位，現行 SendLogDetail 的 UUID 唯一鍵／任務外鍵保持不變。
- 備援唯一鍵 `(source_task_uuid, source_local_generation_id)` 與 `(backup_id, uuid)`；無備援到現行 SendTask 的外鍵。索引涵蓋來源 UUID、備援時間、backup_id、owner_gids GIN。
- reason 限 remote_missing/remote_recreated/manual_reload；remote status 限 unchecked/present/missing/error；snapshot_schema_version 必須正值。舊來源建立時間未知可為 NULL，不能因此捏造版本證據。
- 快照 v1 約定：task_snapshot 使用原任務欄位名的完整 object；stats_snapshot 為完整統計 object 或未知 NULL；mail_template_snapshot 為以 template UUID 為 key 的 metadata object；事件陣列保存原順序。時間戳以整數／ISO 時區字串等 JSON 原生值序列化，實際快照組裝與版本驗證由 TSB-004 負責，本票只建儲存結構。不知道統計計算時間時 stats_snapshot_at 保留 NULL。
- 此 migration 不搬移／刪除業務資料、不建立備援快照。admin-app 已依同意停止；尚未啟動以套用目前測試機資料庫。未來啟動會走 init_db，自動套 additive migration，需操作者確認時機。
