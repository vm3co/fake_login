## 目標與分工

本票處理「清單如何選任務、何時封存」，不重新寫單筆版本同步。其他入口由 TSB-007 接通；同檔案衝突時先整合本票再做入口票。

## 工作項目

1. 同步前對本地與遠端任務都套用可信組織範圍，含備援來源 UUID 的重建檢查。使用者沒有範圍時，不查／不改其他 org 任務。
2. 遠端列表不存在某 UUID，只表示需要單筆確認；不能直接刪除／封存。依 TSB-001 的結果呼叫 TSB-005 核心。
3. 新任務發現範圍對齊十四天政策，與既有任務／備援版本辨識分離；已知來源即使超出日期窗或 `is_archived=True`，也不能因此永久跳過重建辨識。
4. 每輪對有權的來源 UUID 去重查詢，避免同一 UUID 多個備援重複呼叫；限制批次大小／並發，維持可取消，不新增排程。
5. 統一封存規則：`test_end_ut`、`pre_test_end_ut`、`stop_time_new` 中有效正值全部早於十四天門檻才封存；NULL、0、-1 不適用；全無有效值不自動封存。
6. 延長任務時間、任務重建或原先誤封存後，重新計算封存狀態；適用時解除封存。`is_archived` 只控制例行明細刷新，不代表備援歷史版本。
7. 新增、重建、解除封存與影響統計的變更走核心刷新；未變更且只做清單辨識者可避免重抓大量歷史明細，不能再只刷新 added 而漏掉 recreated。
8. 單筆失敗回報 partial，保留該筆原值；整份清單讀取失敗不得把全部本地當作 missing。

## 驗收條件

- [x] org A 使用者同步不查改 org B 任務，不誤封存／備援其他組織資料。
- [x] 缺清單資料、清單 API 失敗或日期窗外任務，不直接被搬移或封存。
- [x] 七天、十四天、剛好門檻、無效結束時間均符合統一規則。
- [x] 已封存任務延期／重建後解除封存且刷新，新版不帶舊資料。
- [x] 舊備援即使不在新任務發現窗內，仍可辨識主系統重建。
- [x] 一筆失敗不隱藏其他已提交成果；結果可供 TSB-009 彙整。

## 執行紀錄

### 實際變更與介面

- 沿用既有未提交的 `task_archive_policy.py`、核心封存參數與兩份測試草稿；修正同版本省略結束時間時，應以套用後任務欄位判斷，不能忽略仍保留的本地時間。
- 新增 `TaskListSyncService(core, clock=time.time, batch_size=20)`，`sync(orgs=..., on_result=None)`：先取得 TSB-001 完整清單，清單失敗／格式錯誤／重複 UUID 在任何寫入前拋錯；合法空清單仍對有權的已知來源逐筆確認。
- 來源為有權現行 UUID、備援來源 UUID、遠端清單 UUID 的聯集；不按 `is_archived` 或建立日期排除已知來源。同 UUID 多份備援只同步一次；僅備援來源沿最近備援的前測旗標，有本地列則以本地為準。現行列或遠端清單已顯示不在範圍時不發單筆遠端查詢，空／無效 org 在遠端讀取前拒絕。
- 每來源先查單筆任務與 metadata、驗遠端組織，再決定新任務發現條件及呼叫 005。新來源以三個有效結束時間的十四天條件判斷，剛好門檻仍納入，全無有效值不推定結束；已知來源不受此發現窗限制。版本、明細、統計與備援仍只有 005 寫入，不先覆寫建立時間。
- 封存與解除封存在 005 同一交易提交，`archive_at` 為本輪固定時間；`TaskSyncResult` 新增 `archive_transition=None/archived/unarchived`。新增、同版更新、重建均完整刷新明細與統計，暫不做未變更歷史任務的輕量最佳化。僅有權備援且遠端不存在時回 `unchanged`，不建空備援、不修改固定快照；完整 missing 觀測欄位延續留 011。
- 同步採並發 1，每批 20 筆（允許 1～100）讓出控制權；單筆錯誤記 `failed_tasks`，其他成功可提交，整輪回 `partial`。取消向外傳遞，當筆由核心 rollback；可用 `on_result` 在每次提交後保存不可變結果，供 009 處理取消前成果。通知一般錯誤只記 `notification_errors`，不把已提交成果改稱 DB 失敗。
- 結果包含 `versioned=True`、`status`、`results`（不可變核心結果）、`added/changed/recreated/backed_up`、`archived_tasks/unarchived_tasks`、`failed_tasks`、`skipped`、`changed_uuids`、`backups_changed`；相容欄位 `deleted=0`、`deleted_tasks=[]`，不把備援稱作刪除。
- `DBUser(task_list_sync=service)` 明確注入後才使用新清單；`check_sendtasks` 工作分支辨識 `versioned`，不再次執行舊明細刷新，保留新增／重建／備援／解除封存／失敗摘要。未注入維持既有行為。封存 worker 重用相同純政策，無效時間跳過，不改排程開關。

### 下游與啟用限制

- 本票交付注入式服務，不替全專案建自動啟用旗標；007 整合其餘入口時建立嚴格 reader／核心／清單服務並注入，不能在其他入口仍走舊寫入時局部正式啟用。舊 `get_se2_sendtasks` 七天 DataFrame 路徑保留給尚未整合的初始化／預熱等入口，不能再當作新清單服務的資料來源；新發現政策已由本票服務接管。
- 009 需把核心結果、通知錯誤、partial 與取消前已提交成果接到工作管理及快取失效；目前工作分支只保留可用摘要，不宣稱全域 job 狀態／快取契約完成。未改 API 身分規則，scope 必須來自可信登入資訊；customer 備援管理仍不開放。
- 未套用現行 DB、未啟動 admin-app、未啟用排程；正式搬移須等 007、009、010～014 及 017 門檻。實際主系統格式與跨入口整合仍由後續票驗收，不能以此替代正式切換。
