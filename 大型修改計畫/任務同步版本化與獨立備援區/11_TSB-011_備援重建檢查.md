## 目標

備援區可檢查主系統是否已重建該來源任務，標記後讓使用者自行決定是否刪除備援。檢查本身不移除備援，也不切換現行任務。

## 工作項目

1. 新增 `check_backup_recreated` 佇列工作，接受明確 backup_ids，或後端重現的有權篩選範圍；不得由前端傳 source UUID 跳過備援授權。
2. 先驗證所選備援 org，再按來源 UUID 去重遠端請求；同來源多份備援各自與來源建立時間比較。
3. 使用 TSB-001 嚴格單筆讀取，正常化比較 create_ut；相同時間代表來源存在但未證實重建，無效時間代表 unknown/error。
4. 將「曾確認重建」與「最近遠端狀態」分開：`recreated_detected_at` 有證據後保留，後來 404／500 不把歷史證據清掉。
5. 最近狀態至少分 unchecked／present／missing／error，另存檢查時間與有效遠端建立時間；不得顯示過時結果為剛驗證。
6. 有效不同建立時間、或核心成功匯入不同版本可標已重建。人工同版本重匯不是主系統重建證據。
7. 共用觀測更新函式供清單／新版本匯入使用，但只更新該執行範圍有權的備援，不藉同 UUID 更新其他 org payload。
8. 工作取消／部分失敗仍保留已完成觀測與備援列表失效資訊，沿 TSB-009 結果規則。
9. 列表提供已重建、尚未證實、未檢查及查詢異常等明確篩選；「尚未證實」不應假稱永遠沒有重建過。

## 驗收條件

- [x] 同 source UUID 選多份備援，只查一次遠端，正確標記每份不同 create_ut 的版本。
- [x] 相同建立時間不誤標重建；無效時間、連線失敗不被標成未重建。
- [x] 已證實重建後再查 404／500，仍保留曾經重建證據並顯示最新查詢狀態。
- [x] 檢查不插入現行任務、不刪備援、不改固定統計／明細。
- [x] 未授權備援不能觸發查詢或取得其結果；混合 org 請求有明確拒絕／排除規則。
- [x] 部分完成後取消，已更新的列表狀態仍刷新。

## 執行紀錄

### 固定請求與授權契約

```json
{"job_type":"check_backup_recreated","params":{"backup_ids":["所選備援ID"]}}
```

- 經既有 `POST /api/jobs/start` 排隊；只接受 backup_ids 參數，非空字串陣列、每值最多36字元，先去重。未指定不代表全部，不接受 source UUID、org 或篩選範圍取代授權。
- 使用010的 backup_scope，customer／空組織拒絕403、未登入401；admin_role=True全範圍，一般user依備援owner_gids。混合有權／無權或不存在ID時整份404，不揭露哪一份失敗、不發遠端查詢。受理及執行時都驗證完整選取，每來源查詢前再次驗證；交易內鎖住並再次驗權。
- JobManager沿原item claim，按來源UUID認領一次，request_params保存backup_ids與source_backups對應。只處理accepted來源，不檢查因其他工作占用而排除的來源。來源穩定按UUID排序，每來源只呼叫嚴格read_sendtask一次，不抓明細／testcase；全為前測備援時明確用pretest，否則test，不用錯誤觸發fallback。

### 觀測與共用邏輯

- 新增 `backup_observation.update_backup_observations` 與 `BackupCheckService`。只更新 latest_remote_status、last_remote_checked_at、last_remote_create_ut、recreated_detected_at，固定任務／統計／樣板／明細不動；不匯入現行任務、不刪備援。
- 狀態：有效遠端建立時間為present；明確TaskNotFound才missing；嚴格讀取錯誤、無效遠端／來源時間為error。missing／error清空本次有效遠端建立時間，不冒用舊時間當新結果。歷史重建證據一旦存在永不清除；同時間不新增證據，人工同版本重匯亦不新增。
- checked_at取遠端查詢開始時間；鎖定備援後，若已有大於或等於此時間的觀測，本次applied=false，不覆蓋較新結果或補上過期證據。同步核心prepare保存observed_at，成功匯入與確認missing均呼叫同一共用函式，且限制可信scope；普通讀取失敗仍不寫現行資料。
- 每來源獨立交易，鎖備援按backup_id排序；查詢期間被刪除／失權來源不再查詢或提交，回局部失敗，其餘成果保留。資料庫寫入失敗rollback該來源，保留先前來源；無效時間不宣稱未重建。檢查時備援為唯一授權依據，不用同UUID新版org代替。

### 結果、取消與篩選

- 結果包含 checked_count（已取得觀測的備援份數）、failed_count（失敗來源數）、backup_observations、backup_check_errors、changed_backup_ids、unchecked_backup_ids、backup_check_items與job_status。backup_observations各列有backup_id、source_task_uuid、latest_remote_status、last_remote_checked_at、last_remote_create_ut、recreated_detected_at、applied。
- 只要觀測已提交且applied，backups_changed=true；changed_uuids=[]、reload_list=false，不使現行任務／明細cache失效。全部可判讀present/missing為completed，部分來源error為partial，全失敗failed；曾證實重建而最近error仍同時保留兩者。
- 每來源提交後透過009 report_outcomes保存結果，取消時使用shield完成已提交回報，再拋BackupCheckCancelled附完整結果。佇列合併備援觀測及changed_backup_ids，不覆蓋前面成果；backup_check_items把成功來源標completed、錯誤來源failed，取消只結束尚未完成item。item reason為backup_check_present/missing/error，不冒用一般任務同步結果。
- `GET /api/task_backups?observation=...` 新增四種值：recreated（曾有證據）、unproven（尚無證據，可能未檢查或查詢異常）、unchecked（最近狀態unchecked）、error（最近狀態error）。原recreated布林與remote_status仍相容，組合使用取交集。
- 顯示範例：recreated_detected_at非空 + latest_remote_status=error 應顯示「曾證實重建；最近查詢失敗」，不能改顯示未重建。證據空 + present只代表本次未證實；證據空 + unchecked代表尚未檢查，不能推論遠端不存在。
