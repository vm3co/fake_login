## 目標與風險

目前 TaskDetail 直接用 `sendtask_uuid` 呼叫現行統計、明細、樣板及匯出 API。不能只換視窗標題或把備援 UUID 傳進去，否則會讀到相同 UUID 的新版資料。

## 工作項目

1. 使用明確資料來源識別，例如 current（UUID + local generation）與 backup（backup_id）；用小型 source adapter 重用現有篩選／表格，避免複製整個 TaskDetail。
2. 備援標頭、統計、明細、樣板 metadata、Excel 所有請求都只走備援 API；不存在或失敗時顯示錯誤，不能 fallback 現行資料。
3. 畫面顯示唯讀、來源 UUID、原版本建立時間、備援時間與統計基準，不能把歷史 today 統計標成現在今日數字。
4. 保留搜尋、分頁、排序、IP 排除、事件次數／最後一次、讀取／點擊／輸入等查閱能力；來源陣列仍由後端快照保留完整。
5. 備援模式隱藏更新、清除觸發資料、主系統下載等會改資料或誤導操作；本地 Excel 只匯出指定備援。
6. localStorage 的 IP 篩選／計分設定按 backup_id 隔離；現行按 generation 隔離，不讓同 UUID 新版繼承舊版顯示設定。
7. 切換同 UUID 不同備援、切換現行與備援、關閉重開時，清理選取／頁碼／舊請求；晚回應不能覆寫另一個已開版本。
8. 現行模式維持既有功能與權限，不因新增 readOnly 就把全部按鈕隱藏；TSB-012 已處理現行版本失效時，本票接上明細重載／關閉規則。

## 驗收條件

- [ ] 同 UUID 新舊版人數不同，開備援看到舊版、開現行看到新版，所有統計／樣板／Excel 相符。
- [ ] 備援 API 失敗不悄悄讀現行，網路記錄沒有備援查閱觸發 live detail/stat/template 請求。
- [ ] 切換多份備援時無舊請求覆蓋、選取或 localStorage 設定串用。
- [ ] 備援無任何可清除觸發紀錄／更新主系統的操作，現行功能不回歸。
- [ ] 原樣板被刪除／改名後，備援仍依快照查閱和匯出。
- [ ] 0 筆備援明細可正常呈現，桌機／手機抽屜內容不遮蓋重要操作。

## 聚焦驗證與交付

lint／build 後用相同來源 UUID 的一份現行與至少兩份備援測試；核對實際請求路徑與 Excel 內容。交付資料來源介面、唯讀限制與手動測試結果給 TSB-016。
