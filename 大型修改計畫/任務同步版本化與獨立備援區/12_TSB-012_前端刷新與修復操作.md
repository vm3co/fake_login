## 目標

工作已提交的變更必須正確反映在畫面，包含移入備援、無 item 清單同步、partial 及取消後已完成的項目。另接上有確認步驟的「備援後重新匯入」，供既有重複資料修復。

## 工作項目

1. JobContext 使用 TSB-009 的失效結果，而不是只監聽 item `completed`；無 items 的工作也能讓現行／備援列表刷新。
2. 針對已提交 UUID 合併失效事件並 coalesce，避免同一輪多筆工作引發連續大量全量查詢；有新增／移轉／來源不明時可明確要求全量刷新。
3. 首次登入／重新進頁時正常載入 authoritative 資料，不為所有歷史工作重播提示；已有輪詢比對仍不得漏掉本次終態成果。
4. 局部查詢成功時，先移除 requested UUID 中確實不存在的任務與統計，再合併新資料；只有成功 authoritative 空集合才可刪本地列。
5. HTTP 失敗、`status:error` 或回應格式錯誤保留目前畫面並顯示錯誤，不把它當作成功空集合。兩個任務／統計請求不一致時不要拼出新舊混合的假結果。
6. 搬移／重建後清理無效勾選及夾住頁碼；已開啟的舊版現行明細需關閉、重新載入或明確提示版本已變更，不靜默顯示舊內容。
7. focus／切換視圖重整能反映其他使用者或排程的已提交變更；不新增高頻全量輪詢。
8. ShowAllTasks、ShowTodayTasks 加入「備援後重新匯入」入口，沿既有 MUI 工具按鈕／選單樣式，顯示範圍、筆數與影響：舊本地紀錄移到備援、現行以主系統重建。
9. 普通「更新」仍是一般同步；強制重匯必須另外確認並呼叫 TSB-008 工作，不能悄悄把所有更新變成 reset。
10. 「更新今日任務寄送現況」維持全部 local todayTasks，確認文案顯示實際筆數，不宣稱只更新搜尋／分頁內資料。
11. 工作中心與提示文字分清更新／已重建／已移入備援／失敗；舊歷史工作資料不完整時也能顯示。將備援失效事件介面交 TSB-013 使用。

## 驗收條件

- [x] 後端移入備援後，現行列表及統計不再留著舊列，跨頁勾選與頁碼正確。
- [x] 清單新增、重建、partial／取消後有提交都會刷新，不只完全成功才刷新。
- [x] API 錯誤不讓現行任務突然消失；成功空集合能確實移除。
- [x] 多個完成事件合併，不造成重複全量請求或舊回應覆寫新資料。
- [x] 人工重匯需要確認，取消確認不送出；操作 UUID、筆數與後端範圍一致。
- [x] 排程／另一使用者更新後，重新 focus 或載入能看到新版本。
- [x] 現行工作中心與歷史工作顯示正常，沒有把備援搬移顯示成永久刪除。

## 聚焦驗證與交付

重用既有測試工具；將必要的 merge／失效判斷抽成小型純函式後用 Node 測試，或沿現有 UI 測試方式，不為此引入全新測試框架。跑修改檔 lint、前端 build，再驗證實際工作輪詢與列表變化。

交付失效事件名稱／payload、備援列表刷新接法、現行明細版本識別與重匯確認流程。

## 執行紀錄

### 實作與交付契約

- JobContext以009的已提交失效資訊建立結果簽章，不只監聽item completed。首次輪詢建立歷史基準、不重播歷史提示；之後新終態、partial、failed、cancelled及執行中新增提交都比較簽章。舊結果缺sync_results時保留completed item相容刷新。
- `taskDataInvalidated` 與 `taskBackupsInvalidated` 的detail共用 `{uuids,versions,reloadList,backupsChanged,backupIds}`；versions按UUID包含generation/revision/status。每輪合併去重，列表250ms合併事件；013訂閱taskBackupsInvalidated，初次進入仍自行讀authoritative資料，不靠歷史事件重播。
- useSendtaskList原子保存tasks/stats快照；任務、統計成功且格式合法、UUID集合一致後才更新。局部成功空集合先移除requested UUID的舊任務與統計；錯誤、重複識別、格式錯誤及集合不一致保留畫面並提示。讀任務、讀統計、再讀任務核對generation/revision，期間變更拒絕套用，不拼接新舊版本。
- 全量／局部刷新以旗標序列化及請求序號拒絕舊回應；刷新進行中再收到失效則合併為下一次全量讀取，不漏其他UUID。首次載入、切換視圖、focus／重新可見及台北跨日正常重載，未新增高頻全量輪詢。StrictMode清理重設in-flight旗標，避免第二次掛載永遠等待。
- 兩列表沿既有validSelectedUuids清理及maxPage夾限。`useTaskDetailInvalidation`處理開啟明細：重建／重匯／搬走、世代不同或無法辨識版本時關閉並提示；同世代更新以revision重新掛載明細，authoritative列表也再次核對版本。未改TaskDetail_new既有使用者草稿。
- `TaskReloadButton`共用MUI圖示／工具列按鈕與確認Dialog，單筆及勾選均可用。打開時固定去重後的目標，顯示名稱／筆數與舊觸發保留備援、新觸發重新開始、同ID舊連結仍可能觸發現行的限制；確認才送force_reload_sendtask與confirm_reload:true，取消不送。送出期間停用重複送出／關閉，失敗保留確認視窗。
- 普通更新維持refresh_sendlog_stats。今日寄送現況仍用完整local todayTasks，確認文案顯示實際數量且不受搜尋、分頁、勾選限制。NotificationBar與工作提示區分重建／重匯／移入備援／失敗／未完成與warning，缺新欄位的舊歷史結果仍可顯示。
