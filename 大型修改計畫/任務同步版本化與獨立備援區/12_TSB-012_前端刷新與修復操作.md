## 目標

工作已提交的變更必須正確反映在畫面，包含移入備援、無 item 清單同步、partial 及取消後已完成的項目。另接上有確認步驟的「備援後重新匯入」，供既有重複資料修復。

## 工作項目

1. JobContext 使用 TSB-009 的失效結果，而不是只監聽 item `completed`；無 items 的工作也能讓現行／備援列表刷新。
2. 針對已提交 UUID 合併失效事件並 coalesce，避免同一輪多筆工作引發連續大量全量查詢；有新增／移轉／來源不明時可明確要求全量刷新。
3. 首次登入／重新進頁時正常載入 authoritative 資料，不為所有歷史工作重播提示；已有輪詢比對仍不得漏掉本次終態成果。
4. 局部查詢成功時，先移除 requested UUID 中確實不存在的任務與統計，再合併新資料；只有成功 authoritative 空集合才可刪本地列。
5. HTTP 失敗、`status:error` 或回應格式錯誤保留目前畫面並顯示錯誤，不把它當作成功空集合。兩個任務／統計請求不一致時不要拼出新舊混合的假結果。
6. 搬移／重建後清理無效勾選及夾住頁碼；已開啟的舊版現行明細需關閉、重新載入或明確提示版本已變更，不靜默顯示舊內容。
7. focus／切換視圖重整能反映其他使用者或排程的已提交變更；不新增高頻全量輪詢。
8. ShowAllTasks、ShowTodayTasks 加入「備援後重新匯入」入口，沿既有 MUI 工具按鈕／選單樣式，顯示範圍、筆數與影響：舊本地紀錄移到備援、現行以主系統重建。
9. 普通「更新」仍是一般同步；強制重匯必須另外確認並呼叫 TSB-008 工作，不能悄悄把所有更新變成 reset。
10. 「更新今日任務寄送現況」維持全部 local todayTasks，確認文案顯示實際筆數，不宣稱只更新搜尋／分頁內資料。
11. 工作中心與提示文字分清更新／已重建／已移入備援／失敗；舊歷史工作資料不完整時也能顯示。將備援失效事件介面交 TSB-013 使用。

## 驗收條件

- [ ] 後端移入備援後，現行列表及統計不再留著舊列，跨頁勾選與頁碼正確。
- [ ] 清單新增、重建、partial／取消後有提交都會刷新，不只完全成功才刷新。
- [ ] API 錯誤不讓現行任務突然消失；成功空集合能確實移除。
- [ ] 多個完成事件合併，不造成重複全量請求或舊回應覆寫新資料。
- [ ] 人工重匯需要確認，取消確認不送出；操作 UUID、筆數與後端範圍一致。
- [ ] 排程／另一使用者更新後，重新 focus 或載入能看到新版本。
- [ ] 現行工作中心與歷史工作顯示正常，沒有把備援搬移顯示成永久刪除。

## 聚焦驗證與交付

重用既有測試工具；將必要的 merge／失效判斷抽成小型純函式後用 Node 測試，或沿現有 UI 測試方式，不為此引入全新測試框架。跑修改檔 lint、前端 build，再驗證實際工作輪詢與列表變化。

交付失效事件名稱／payload、備援列表刷新接法、現行明細版本識別與重匯確認流程。
