## 目標

Dashboard 增加獨立「備援任務」視圖，歷史資料不混入現行全部／今日任務與統計；使用者能識別同 UUID 的多個備援版本並自行管理。

## 工作項目

1. Analytics 使用明確 view mode：today／all／backups，保留既有列表切換及選取行為；備援時不讓 StatCards 的現行篩選意外切走或污染資料。
2. 新增 `ShowBackupTasks.jsx`，列表採既有 MUI 視覺與表格慣例，不改全站設計，不做 landing page。
3. 顯示任務名、原始 UUID、原版本建立時間、備援時間、備援原因、明細數、重建標記及最近檢查結果／時間；顯示版本標籤但不修改 UUID。
4. 提供搜尋、分頁、必要排序及全部／已重建／尚未證實／未檢查／查詢異常篩選；用後端固定列舉，不以錯誤狀態推導「未重建」。
5. 列表選取用 backup_id，不用 source UUID；同 UUID 的兩份備援可分別選取與操作，並正確處理全選本頁、清除、刪除後頁碼。
6. 「檢查是否重建」針對選取範圍或明確顯示的篩選範圍送工作，範圍／筆數清楚，不僅提示開始還要接收 TSB-012 的失效刷新。
7. 本地 Excel 直接使用 backup_id 匯出，不呼叫主系統；明細按鈕保留清楚的 `backup_id`／唯讀資料來源介面，TSB-014 再串實際抽屜。
8. 刪除按鈕依後端能力與 org 授權呈現；確認顯示確切版本、備援時間與永久刪除影響，說明現行與其他版本不受影響。成功只移除被刪 backup_id。
9. 為空清單、載入、檢查中、無權限、失敗、下載與刪除處理完整狀態；工具 icon 使用既有 MUI 圖示並有 tooltip／可及名稱。
10. 控制備援查詢與目前視圖生命週期，必要時新增小型 hook；不新增整套全域狀態框架。

## 排除事項

- 不在本票寫備援明細畫面、不讓歷史版更新主系統、不新增每日資料庫備份。
- 客戶帳號本次不開放備援管理，不修改其既有現行任務顯示。

## 驗收條件

- [ ] 三視圖切換不混資料，備援數字不計入現行 StatCards／todayTasks。
- [ ] 同來源 UUID 多份備援可獨立選取、匯出與刪除，不操作錯版本。
- [ ] 已重建與查詢異常可同時合理呈現，失敗不抹掉曾證實重建標記。
- [ ] 同 org user 可操作授權備援，跨 org 列表不洩漏，後端拒絕時正確顯示。
- [ ] 檢查工作完成／partial 後列表刷新，刪除最後一頁最後一筆不留空白頁碼。
- [ ] 桌機與手機控制項可用、不互相遮蓋，表格保留可預期的橫向捲動。
