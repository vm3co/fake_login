## 目標與問題

目前分頁中途失敗仍可能回傳前幾頁，空資料、查詢失敗與任務不存在又可能被包裝成相同值。先建立可靠的完整讀取結果，讓下游不會把暫時錯誤當成主系統已刪除任務。

## 範圍

1. 為任務列表、單筆任務與寄送明細建立明確結果：完整成功（可為空）、確認任務不存在、查詢失敗。使用小型結果型別或明確例外即可，不建新 API 框架。
2. 任務與明細分頁要求完整取得；任一頁失敗、資料形狀不符或必要欄位缺失，整次結果不得宣稱成功。
3. 單筆任務的不存在判斷只接受可信任的任務層訊號。HTTP endpoint 404、登入頁、401／403／500、無效 JSON 不可直接當作任務刪除。
4. 建立時間正規化為有效整數再比較，字串數字與整數等價；缺值／無效值不得觸發版本替換。
5. 不在 metadata 取得失敗時寫入 `False/-1/0` 覆蓋已知資料；回報單筆失敗或保留既有欄位，並讓上層知道不完整。
6. 定義取得新版本完整快照的讀取程序：單筆資料、全部明細及所需 testcase 欄位，下載前後核對建立時間。兩次不同則丟棄快照，有限次重試或回報可重試錯誤。
7. 合法 0 筆明細允許成功；若主系統提供可信總筆數，核對分頁與總數。`test/pretest` fallback 不得把錯誤當作空集合後轉為成功。

## 聚焦驗證

以 mock HTTP 回應／分頁結果測試，不呼叫正式主系統。對不存在格式使用去識別化回應樣本；若目前只能確認 HTTP 404 而無法辨別資源類型，記為受阻條件，下游保守保留資料。

## 交付給下一票

記錄結果／例外的欄位、空集合語意、確認不存在證據、版本正規化規則，以及完整快照準備函式的位置，供 TSB-005、TSB-011 共用。

### 實際交付介面

- `get_se2_data.get_task_reader()` 建立 `SE2TaskReader`，沿用 URL／TLS 設定，每次請求即時取 headers，不複製憑證或記錄敏感回應。
- `read_sendtasks(start_time=..., end_time=..., keyword=...)` 回完整驗證任務 `list[dict]`；合法無資料為 `[]`，不回 `None`。
- `read_sendtask(task_uuid, sendlog_type="test")` 回 `{"data": normalized_task, "metadata": validated_metadata}`；不使用失敗／空集合 fallback。
- `read_sendlog(task_uuid, sendlog_type=...)` 要求明確 test／pretest，回完整明細清單（可空），保留原始事件陣列；若有 metadata.total 則核對數量與跨頁一致性，缺 total 時使用既有 record_page／短頁終止契約，無法證明主系統未回報的隱藏筆數。
- `read_task_snapshot(task_uuid, sendlog_type="test")` 依任務 pre_test_enable 選明細類型，取得 testcase 與前後任務；回 `TaskSnapshot(task, metadata, sendlogs, testcase, create_ut, sendlog_type)`。testcase 至少驗證結構與來源 UUID，其餘業務欄位由後續同步 mapping 明確選取，不用預設值掩蓋讀取失敗。
- `normalize_timestamp` 接受正整數、整數浮點與數字字串；布林、缺值、負數、非整數、非數字、無限值拒絕；明細時間可明確允許 0。
- `TaskReadError.reason/http_status` 提供無敏感回應內容的錯誤；`TaskNotFound` 僅適用已實測的 get_sendtask + test + HTTP404 + 整數 sub_code40400。pretest 不存在格式尚無證據，先當普通讀取錯誤；不以任意 HTTP404 或 HTTP200 業務40400猜測不存在。
- `TaskVersionChanged` 表示前後建立時間／pre_test_enable 改變，或讀取後檢查時才消失。下游應有限次重新準備或回報重試，不可直接依過期快照刪除／搬移。
- 本票採獨立嚴格讀取器，保留既有 `_send_post`、`get_sendtasks/get_sendtask/get_sendlog`、DataFrame wrapper 與 DBUser 讀寫流程不變。TSB-005／006／007 必須切換這些呼叫並移除舊 metadata 補零流程，不能把本票完成當成現有按鈕已安全。
