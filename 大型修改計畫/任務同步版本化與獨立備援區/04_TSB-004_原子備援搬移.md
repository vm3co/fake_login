## 目標

將一個完整本地版本搬到獨立備援表，資料仍保留在 PostgreSQL。快照與現行移除必須是同一交易，任何一步失敗不得留下半份備援或消失的任務。

## 範圍

1. 建立接受既有 transaction/session 的備援函式，不自行 commit；呼叫者可在同一交易繼續插入新版本。
2. 鎖定後讀取任務全欄位、現行統計、明細全部原始欄位、完整事件陣列及當時匯出所需的本地樣板 metadata。
3. 保存來源組織、本地 generation、主系統建立時間、備援時間與原因：`remote_missing`、`remote_recreated`、`manual_reload`。
4. 寫入備援標頭與明細，全部成功後才移除現行明細、統計與任務；依實際 FK 確認刪除順序，不依賴 ORM 記憶體物件的隱含動作。
5. 保留未提供／已不存在的樣板資料為可辨識的缺值，不為備援額外呼叫主系統補資料，也不以目前時間冒充未知統計基準。
6. 重試同本地 generation 搬移不產生第二份備援；無現行資料時不得建立空備援。
7. 不連帶刪除 `CustomerTask` 或客戶可見 UUID 關聯；保留現有來源關聯，讓同 UUID 新版可沿既有流程顯示。

## 觸發事件邊界

備援保存取得搬移鎖後讀到的已提交明細。搬移後不追加歷史事件；因舊明細 UUID 已不在現行表，晚到事件應不匹配，而不是轉寫備援。

主系統明細 UUID 會重新產生是此計畫的已確認前提；若測試發現主系統可能重用完全相同明細 UUID、且事件無法區分世代，必須列阻礙，不得假稱已能可靠區分。人工同版本重匯也需在 TSB-008 說明同 ID 的事件語意。

## 驗收條件

- [x] 搬移後現行查不到任務，備援仍有完整任務、明細、統計及所有本地事件。
- [x] 備援明細第 N 筆失敗、移除現行失敗時，整次 rollback，現行資料原樣保留。
- [x] 交易外看不到半完成搬移；備援來源版本不重複。
- [x] 任務原始 UUID 未被修改；現行客戶關聯未被 cascade 清除。
- [x] 搬移前已提交事件保留，搬移後的舊事件不追加備援。
- [x] 樣板之後被修改／刪除，不改變已保存的 metadata snapshot。

## 聚焦驗證

以專用 PostgreSQL 驗證交易中途故障、並發明細更新與重試。驗證備援前後原始事件陣列與筆數，不只驗證頁面顯示的最後一筆。

## 交付給下一票

提供呼叫方式、是否有現行資料的回傳、產生的 `backup_id`、來源 generation、備援原因，以及供 API 使用的 payload schema。

### 實際交付契約

- `transfer_task_to_backup(locked, reason=...)` 必須在 `task_sync_transaction` 裡呼叫，使用 `locked.session`，不另開session、不自行commit。呼叫前不得修改／flush來源任務；呼叫者先做遠端準備，進guard後先搬移，再建立新版。
- `LockedTask.require_active()` 限制guard生命週期；離開交易後不能使用舊物件搬移／鎖明細。例外必須向外傳到guard以rollback，不得吞掉後繼續提交。
- 回傳 immutable `BackupTransferResult(backup_id, source_task_uuid, source_generation, reason, detail_count, created)`。備援ID在外層commit前是暫定結果，通知／快取處理應在commit後。
- 同guard同reason重呼叫回相同ID、created=False；不同reason重呼叫報衝突。現行不存在回 backup_id=None、generation=None、created=False，不造空備援。舊expected重試由guard拒絕；異常的現行與同generation備援並存時報衝突，不以舊備援為理由刪現行。
- 鎖定順序為任務guard → 按id鎖明細 → 鎖統計；快照讀取在明細鎖後。寫完備援標頭與全部明細後刪現行明細、統計、任務，flush仍在同交易。CustomerTask及CustomerAcct.sendtasks不改動。轉移完成locked.task=None，外層可繼續建立同UUID新generation。
- 快照v1：task_snapshot完整原SendTask欄位（含原id與本地generation/revision）；stats_snapshot完整原統計，缺資料為NULL、stats_snapshot_at為NULL；mail_template_snapshot以明細與任務mail_template的UUID聯集為key，missing為JSON null。metadata保存本地名稱、主旨、原始tag/附件UUID、owner、建立更新時間、寄件人／地址與model存在時的weight_score，不保存郵件HTML內容、不呼叫SE2補名稱或附件。
- TaskBackupDetail複製所有原明細欄位，僅排除原id（備援產生獨立id），保留原uuid/sendtask_uuid與完整事件陣列。JSON序列化拒絕NaN／未知型別，datetime須有時區且轉ISO字串；不隨意str()掩蓋無法序列化的資料。
- 備援固定不追加；主系統新版明細UUID不同是本方案前提。人工同版本重匯若重用明細UUID，後續新事件仍匹配現行同ID（TSB-008已記錄），此函式不聲稱能辨識同ID事件世代。
