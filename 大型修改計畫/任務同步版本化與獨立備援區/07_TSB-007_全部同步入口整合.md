## 目標

所有入口都先讀舊版本再套用核心同步，尤其禁止先 upsert `sendtask_create_ut` 而掩蓋重建。這張票只接線與保留各入口範圍，不複製版本演算法。

## 入口覆蓋表

| 入口 | 要驗證的行為 |
| --- | --- |
| ShowAllTasks／ShowTodayTasks 單筆、勾選更新 | 指定 UUID 經 org 授權後走核心，404 改備援而非永久刪除 |
| 更新今日任務寄送現況 | 維持 local `todayTasks` 全部 UUID；不默默改為目前篩選／分頁 |
| 手動更新今日建立任務 | 發現後直接交核心，不能先批次 upsert |
| 今日建立任務排程 | 與手動語意一致，system scope 不限 org |
| 依名稱搜尋後匯入／upsert by UUID | 名稱只用來發現，不作版本鍵；匯入前比較既有版本 |
| `create_task_api.create_sendtask` | 啟動後不要先覆寫本地建立時間，testcase 欄位與核心新版本一致 |
| nightly 同步 | 先用 TSB-006 清單政策，再用核心刷新，不重複套兩種世代判斷 |
| 今日未完成排程 | 保留選取條件，選到的任務走核心 |
| 初始化空表、啟動預熱 | 不繞過版本規則，也不因 warming 整批寫入舊資料 |
| `refresh_sendlog_stats` 的其他呼叫者 | 回傳狀態改依新契約，不能把 backed_up 當 error 或再計算已移走任務 |

## 工作項目

1. 依表逐項整合，移除任務同步流程內的 404 永久刪除及「建立時間變更只更新標頭」舊分支。
2. 將 `skip_sendtask_sync` 等可能繞過版本辨識的參數限縮／移除或重定義，不能成為不比較世代的捷徑。
3. 保持既有入口的權限、請求參數與排程開關；必要的回應遷移由 TSB-009 統一，舊停用 API 的 410 不必重新開放。
4. 保留客戶任務追蹤／可見 UUID 關聯，啟動後同步錯誤須可觀察，但不得把已成功的主系統啟動誤稱失敗。
5. 確認執行中的任務是否有已提交成果，供取消／partial 結果交付；不讓某個入口吞掉同步錯誤後回全部成功。
6. 以程式搜尋證據檢查所有 SendTask 寫入呼叫，確認相關同步路徑沒有提前 upsert 建立時間；不要把無關管理操作一併重構。

## 排除事項

不改手動永久刪除現行任務的既有權限規則；本次 org 刪除擴充針對備援 API。不同意圖的顯式刪除與自動同步的保留規則必須區分。

## 驗收條件

- [x] 入口表每列都有 mock／整合測試，能重現同 UUID、create_ut 改變並驗證核心在寫入前被呼叫。
- [x] 單筆／勾選及排程遇確認不存在時保留到備援，而不是永久刪除。

## 聚焦驗證與交付

依入口逐批跑最窄測試，最後交付已核對的入口表與呼叫者清單。將不相容結果或參數變更交給 TSB-009，不留「應該沒有人呼叫」的未驗證假設。

## 執行紀錄

### 實際變更與入口對照

| 入口／呼叫者 | 整合方式與驗證 |
| --- | --- |
| ShowAllTasks／ShowTodayTasks 單筆、勾選 | 保持 `/api/jobs/start`；工作受理時驗本地 org，執行時再次傳可信 org 到核心。API 測試確認跨 org UUID 不進核心，真 PG 工作函式驗證重建及確認不存在。 |
| 更新今日任務寄送現況 | 前端仍由 `todayTasks.map(...)` 傳完整 UUID，未改篩選、分頁或前端程式；後端沿相同逐項工作處理。 |
| 手動今日建立／今日建立排程 | 共用 `DBUser.sync_today_created_tasks(orgs=...)`，嚴格讀取今日清單後逐筆核心同步，不先 upsert；手動與 system 排程分別傳可信 org／None。摘要依核心實際 added／updated／recreated，不以是否已有本地列猜測。 |
| 名稱搜尋／匯入 | 搜尋使用嚴格清單，只發現不寫入；`authorize_sync_candidate` 先核對本地組織，無本地才讀嚴格單筆核對遠端組織。工作執行時直接走核心，不再先 upsert 後刷新第二次。 |
| `create_task_api.create_sendtask` | 保留主系統真正 UUID、CustomerTask 與客戶可見關聯。啟動成功後核心匯入完整 testcase／明細／統計；本地關聯或同步錯誤獨立放 `local_errors`／`sync_status`，不誤報主系統啟動失敗。真 PG 驗重建／備援，mock 驗客戶關聯與同步失敗。 |
| nightly／清單同步 | DBUser 預設延遲建立 006 清單服務，nightly 只跑一次清單政策，不再以另一輪統計刷新重複同步；有權來源不受封存／發現窗永久排除。 |
| 今日未完成排程 | 保留 `today_earliest_plan_time != 0`，以及 `todayunsend > 0 or todayfailed > 0` 的選取條件，選中 UUID 走核心；未改排程開關與時刻。 |
| 初始化空表 | SendTask 不再走 batch_create／七天 DataFrame 匯入，改由 006；統計空表補建也走核心。部分失敗拋附帶成果的 `TaskSyncIncomplete`，不宣稱初始化全部成功。 |
| 啟動預熱 | 移出 lifespan 內部為可測試 `run_cache_warming`，仍選原本未封存 UUID；版本判斷與寫入走核心。追蹤器保留 partial／failed 與取消前摘要。 |
| 其他明細／統計入口 | `check_sendlog`、`sendlog_write`、`upsert_sendtasks_by_uuids`、`_sync_sendtask_from_se2` 均代理核心；`refresh_sendlog_stats` 不自行計算／upsert 已被搬走任務。 |

- 新增 `services/task_sync_entrypoints.py`，`sync_task_batch(core, uuids, orgs=..., on_result=None)` 以 UUID 去重、逐筆執行；一輪固定 `archive_at`，封存與解除封存仍由核心交易處理。衝突不重放舊快照；各次核心呼叫均重新 prepare。
- `DBUser(task_sync=..., task_list_sync=...)` 仍可注入測試依賴；未注入時延遲建立 `TaskSyncService(async_session, strict_reader)` 與 `TaskListSyncService(core)`，不留下新舊刪除流程選擇分支。部署限制靠服務仍停止及 017 作業，不新增自動開關、不啟動正式寫入。
- `TaskSyncStatuses` 是相容 UUID → status 的 dict，另有 `results`（不可變、已提交核心結果）、`errors`、`notification_errors`。`added/updated/recreated/backed_up/unchanged` 均不是讀取失敗；批次例外回 error，但不隱藏其他已提交結果。`summarize_task_sync` 交付分類清單、changed UUID、backups_changed、job_status 與純 JSON 摘要。
- `TaskSyncCancelled` 繼承 CancelledError 並附 `.results`；批次與逐項工作／清單代理保留取消前成果；`TaskSyncIncomplete` 供初始化失敗帶出部分結果。工作項目回報／Telegram 故障另記，不能反稱核心 rollback。
- 保留寄送開始通知，移至核心成功返回後讀已提交統計，核對 generation／revision，再發送；通知失敗不改 status。完整 Redis 快取與佇列取消成果持久化仍留 009。
- `ignore_archived`／`skip_sendtask_sync` 保留相容簽章但不再略過世代判斷；本票先完整刷新選中任務，不實作只檢查版本、不讀明細的最佳化。`upsert_sendtasks_by_uuids` 另回 statuses，backed_up／unchanged 不當作成功匯入清單。

### 呼叫者搜尋與保留邊界

- 搜尋 `refresh_sendlog_stats/check_sendlog/sendlog_write/upsert_sendtasks_by_uuids` 與 SendTask 的 upsert／update／delete：有效同步入口已移除提前寫入；初始化 SendTask 在通用 batch_create 前走核心並 continue。
- 舊 `_build_sendtask_record_from_detail`／`_build_testcase_detail_fields`／`get_se2_sendtasks` 為未被有效同步入口使用的只讀相容 helper，未擴大刪除無關程式。`data_api.refresh_and_notify` 為無呼叫者的舊內部 helper，不重新接通；四個停用資料端點仍 410。
- `data_api` 的顯式手動刪除現行任務仍保留，與本票自動同步遇不存在的備援規則不同。未修改 data_api／models／database 或既有前端草稿，未變更原登入權限或客戶備援管理規則。
