## 目標與邊界

各票自行完成單元／聚焦整合測試，本票驗證跨模組的資料不遺失、世代隔離、權限與使用者工作流。不是等到本票才替所有功能補單元測試，也不藉驗收修無關問題。

## 測試環境門檻

1. 使用專用 PostgreSQL 測試資料庫與獨立 Redis namespace／實例；測試必須檢查目標環境，不得誤用現行 Compose 的正式資料庫／事件 queue。
2. SE2 全部用可控制的 fake／mock 回應；若需真實樣本，只使用去識別化資料，不在測試輸出保存受測者敏感內容。
3. 沿既有 pytest、Node 測試風格，優先擴現有檔案；真實 constraint／row lock／rollback 需用 PostgreSQL，不能只用 SQLite 或 AsyncMock 宣稱通過。
4. 先記錄現有基線失敗，區分本次引入與原有問題；沒有環境就標「待驗收」，不假稱完成。

## 必驗矩陣

| 類別 | 案例 | 必驗結果 |
| --- | --- | --- |
| 刪除備援 | A 版 3 人且有本地事件，確認 404 | 現行移出，備援 3 人、統計、全事件陣列完整 |
| 重建 | 同 UUID B 版 5 人 | 現行僅 B 版 5 人，A 不混入；備援可查閱／匯出 |
| 無 404 空窗 | 直接從 A 讀到不同 create_ut 的 B | 同樣先備援再乾淨替換 |
| 多版本 | A → B → C | 三份版本識別明確，多份備援同 UUID 不衝突 |
| 同明細 ID | 不同備援重複原明細 UUID | 歷史唯一鍵正確，不影響現行唯一限制 |
| 同版本 | 反覆更新同 UUID／create_ut | 不增重複明細，本地 `second_*` 不被抹掉 |
| 合法空資料 | B 版完整 0 筆明細 | 正常新版本 0 筆，不誤當讀取失敗 |
| 讀取故障 | 第二頁失敗、metadata 失敗、401、403、500、壞 JSON | 不搬／不清／不歸零，結果為 error／partial |
| 版本故障 | create_ut 缺失、無效、下載前後改變 | 不套混合快照，不破壞舊版 |
| 寫入故障 | 備援中途、新明細、統計任一步失敗 | 同一交易 rollback，沒有半份備援或消失任務 |
| 並發 | 手動、清單、scheduler、warming 同 UUID | 鎖定有效、不多搬、不讓過期成功或 404 覆蓋新版 |
| 不同任務並發 | A／B UUID 同時同步 | 不受單一全域鎖全部串行化 |
| 重試／取消 | 重試相同來源；已提交一筆後取消 | 冪等、鎖釋放、已提交失效資訊仍可觀察 |
| 人工修復 | create_ut 已覆寫且累積兩批人 | 備援後重匯可修，非 email 去重 |
| 範圍 | org A 操作，org B 現行／備援存在 | 不查改 B，不誤封存／備援 B |
| 備援權限 | admin、同 org、跨 org、空 org、customer、未登入 | 每條列表／明細／匯出／檢查／刪除 API 都正確 |
| 組織變更 | 同 UUID 新版換 org | 新版授權不影響舊備援快照權限 |
| 刪備援 | 刪 X，另有 Y 與現行 C | 只刪 X，Y／C／客戶來源關聯不變 |
| 重建檢查 | 不同／相同 create_ut、後續 404／500 | 曾證實重建不被清掉，最近狀態另外顯示 |
| 歷史匯出 | 樣板修改／刪除、主系統離線 | 仍匯出對應備援快照，筆數與事件一致 |
| 事件邊界 | 搬移前提交、搬移後晚到舊明細事件 | 前者保留，後者不寫備援或新版 |
| 快取 | Redis 清除失敗、舊格式、晚到舊 cache write | 版本核對使舊值失效，不返回舊世代人員 |
| 封存 | 七／十四天、NULL、0、-1、延期／重建 | 統一十四天與解除封存，版本辨識不被封存略過 |
| 畫面刷新 | 無 item 清單、移轉、重建、partial／取消 | 正確新增／移除列與統計，無過期勾選／頁碼 |
| 明細來源 | 同 UUID 新版及兩份備援依序開啟 | 標頭、明細、統計、樣板、Excel 不混來源 |
| 日期 | 台北午夜、UTC／台北／其他瀏覽器時區 | 秒／毫秒一致，起訖剛好邊界、明天／下週分類正確 |
| 回歸 | 普通更新、既有匯出、客戶現行任務、停用 API | 既有能力維持，備援不進客戶管理，舊 410 保持 |
