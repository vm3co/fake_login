## 1. 修改目標
新增「AI 指定生成需求」，並升級「新增自訂頁面」，支援可持續編輯的多欄位表單。新版頁面在瀏覽器送出前依欄位設定遮罩，密碼僅記錄填寫狀態；後續編輯不再呼叫 AI。

## 2. 範圍界線
- **包含**：結構化生成、欄位新增／刪除／排序、格式驗證、實際遮罩、Logo 三模式、規格保存、儲存後編輯及新版提交流程。
- **相容**：保留原 AI 入口、舊頁面編輯、權限、網域綁定、下載、複製及跳轉行為；新版頁面取消任意 HTML 覆蓋。
- **排除**：舊頁面自動轉換、歷史資料遮罩、報表改版、歷史表單版本查詢，以及特殊欄位的外部 API、跨欄位判斷與任意 JavaScript。
- 遮罩只適用新版結構化頁面；介面須區分新版與舊頁面，不能宣稱整套系統皆已遮罩。

## 3. 已確認需求
**建立與編輯**
- 新 AI 入口提供必填分頁標題與 H1、選填說明、欄位清單、風格描述、模型選擇、一張選填參考圖片；提交按鈕文字預設「送出」。
- 網址 ID 選填：新建與複製留空時由後端產生唯一 ID；編輯留空時保留原 ID。自行指定時前端預查、生成／儲存前重查，後端仍以 DB 唯一限制與不覆蓋檔案寫入處理競態。
- 欄位初始 1 個，至少 1 個、最多 10 個；名稱必填、新增預設純文字、必填開關預設開啟，支援上下排序。
- 「新增欄位」按鈕固定放在欄位列表底部；新增後聚焦並捲動到新欄位名稱。
- 固定類型為純文字、email、密碼、身分證、電話；身分證只檢查英文字母＋`1`／`2`＋8 個數字，電話只接受 `09`＋8 個數字。
- 「指定內容」僅首次 AI 指定生成可用，限單一輸入欄位及允許的宣告式格式規則；無法表達的要求須提示修改，不能靜默降級。
- 已保存的特殊欄位可改名稱、必填及遮罩、排序、刪除或轉成固定類型；特殊規則唯讀，不可新增同類型。
- 特殊欄位刪除或轉型前提醒儲存後無法透過編輯器恢復；所有操作先修改草稿，取消不影響原頁面，按儲存才生效。
- 新版頁面可持續修改標題、說明、按鈕文字、Logo 及欄位；AI 遵循固定欄位結構與共用樣式，避免增刪欄位破壞版面。

**Logo 與生成流程**
- 三種互斥模式：「AI 生成（預設）／留空／上傳自訂 Logo」；參考图片與 Logo 分開處理。
- 自訂 Logo 由程式在生成後置入，不交由 AI 重繪；留空模式保留空容器。生成後仍可替換或移除。
- AI 第一次尚未產生有效結果時不掛載預覽 iframe；設定區使用完整寬度。第一個通過驗證的結果立即顯示；重新生成時保留上次有效預覽並標示新結果尚在生成。
- AI 輸出若未通過欄位、固定容器、必要標記或腳本契約，系統以完全相同的需求自動生成，包含第一次最多三次。只有輸出契約錯誤會重試；模型連線、認證、限流、取消與前置輸入錯誤立即回報。三次皆不合格才回覆最終錯誤，不能據此斷言使用者需求錯誤。
- 新入口不加入下載觸發、參考網址或 DESIGN.md；生成結果須通過結構檢查，不符則不能儲存。

## 4. 遮罩規則
| 欄位類型 | 可選模式 | 新增預設 |
|---|---|---|
| 純文字、email | 不遮罩、全部遮罩、保留前 N 碼、保留後 N 碼 | 全部遮罩 |
| 身分證、電話、特殊指定內容 | 全部遮罩、保留前 N 碼、保留後 N 碼 | 全部遮罩 |
| 密碼 | 僅記錄填寫狀態，不提供保留碼數 | 填寫狀態 |

- N 為正整數；長度大於 N 時保留指定端 N 碼，其餘以 `*` 取代；長度為 2～N 時僅隱藏另一端 1 碼；單字元全遮罩，選填空值維持空值。
- 例如保留後 6 碼：`123456789 → ***456789`、`123456 → *23456`、`123 → *23`、`1 → *`；保留前 6 碼：`123456 → 12345*`、`123 → 12*`。
- 遮罩設定搭配假資料示意；改變欄位類型時重新檢查模式，不能把「不遮罩」帶入身分證、電話或特殊類型。

## 5. 技術方案與影響
- `CreateUrl.jsx`：新增入口、共用欄位編輯器、遮罩控制、Logo 模式、草稿與預覽整合；必要時拆出小型元件。
- `trigger_page_api.py`：新增結構化契約、受控生成與 HTML 檢查、更新自訂模板；隔離新舊提示詞，避免固定「登入」標題覆蓋指定內容。
- `models.py`、`database.py`：新增 nullable 頁面規格與編輯修訂號，保存穩定欄位 ID、順序、類型、驗證及遮罩設定；舊資料維持空規格。
- 新版使用獨立提交邏輯，不接入會收集完整值的舊監聽器；`recordingLogin.js` 保留供舊頁面使用。
- `record_api.py` 增加新版接收流程，依伺服器確認的頁面、修訂與欄位規格檢查已遮罩資料；必要時調整 Trigger App 模型 以讀取規格。
- 新版請求包含欄位 ID 與處理後的值，不包含原始值副本；後端依保存順序組合為既有 ` | ` 字串，沿用事件與報表流程，不信任前端自報的遮罩設定。

## 6. 實作順序
1. **契約與遷移**：定義規格、遮罩規則、修訂號及新版請求；完成條件為新舊資料可共存、遷移可重跑、非法設定可明確拒絕。
2. **HTML 與規格工具**：使用 parser 處理受控容器、欄位與標題；檢查數量、順序、類型、驗證、必要標記及禁止的提交邏輯，保留 Jinja 語法。
3. **保存生命週期**：完成讀取、更新、複製、改網址 ID、刪除與修訂衝突處理；保存失敗須保留原規格與 HTML，避免部分更新。
4. **新版提交與遮罩**：先驗證、再遮罩、再傳送；後端查核契約並接既有事件流程。開著舊修訂頁面送出時拒絕並要求重新整理，不自行套錯規則。
5. **管理介面與生成**：整合自訂模板、AI 入口、欄位編輯、特殊欄位警告、Logo 及即時預覽；預覽隔離腳本與提交，不能產生正式記錄。
6. **體驗修訂**：網址 ID 改為選填與預查；新增欄位按鈕移至列表底部；AI 初次生成前隱藏預覽；結構驗證失敗最多三次自動生成；短輸入改為僅隱藏一碼。
7. **驗證交付**：完成以下測試，記錄通過項目、環境限制及未完成項目，不以編譯成功代替功能驗收。

## 7. 驗證與驗收
- 遮罩測試涵蓋全部模式、空值、1 字元、長度小於／等於／大於 N、非法 N、Unicode、含 `*` 的輸入、密碼固定標記及類型切換。
- 網址 ID 測試涵蓋留空自動產生、指定 ID 重複、編輯自身 ID、可用性預查與生成前攔截；預查不保留 ID，儲存衝突仍回 409。
- 欄位測試涵蓋 1／10／11 欄位、最後一欄不可刪、必填／選填、格式正反例、排序、特殊欄位取消／確認、儲存後重新載入及複製後獨立修改。
- 生成與版面測試涵蓋首輪成功、第三輪成功、三次失敗、供應商錯誤不重試、缺欄、多欄、錯誤類型、缺少標記、Logo 三模式、圖片失敗、長標題、10 欄位、桌面與手機捲動及無重疊。
- 提交測試檢查正常新版請求、日誌與儲存中沒有應遮蔽的原始內容；拒絕未知欄位、過期修訂、不合規密碼值，確認預覽不提交及成功後跳轉。
- 後端沿用 pytest 設定 與 fixture，mock 模型並補少量實際模型驗證；前端做範圍 lint、`npm run build`、瀏覽器驗收及舊流程回歸。

## 8. 風險與技術預設
- **安全限制**：後端能檢查契約與值的形狀，但不能證明任意客戶端真的執行過遮罩；不得記錄新版請求原文或在錯誤回應回顯輸入。選擇「不遮罩」的文字與 email 仍可能包含個資。
- **待計畫確認的預設**：N 限 1～100，以 Unicode code point 計數；參考圖限 PNG／JPEG／WebP、5 MiB，Logo 延續既有格式含 SVG、5 MiB，並驗證解碼及安全處理。
- **實作時查證**：HTML parser 的 Jinja 相容性、頁面與實際網域／觸發 URL 的可信對應、資料與檔案失敗回復，以及現有測試環境；不得覆蓋工作區既有未提交異動。
- **已接受限制**：舊頁面及歷史值不回溯遮罩；欄位改動後歷史記錄可能無法按位置直接比較，儲存前須提醒；不宣稱可自動證明任意自然語言規格完全正確。
